# 渲染接口约定

这份文档说明当前渲染层各模块的职责和边界。内置核心PBR和主方向光阴影已接通，但没有完整材质编辑器、IBL或所有光源阴影。

## 1. 模块职责

渲染相关代码按下面的关系协作：

```text
SceneLighting  -- 场景里有哪些光源
       │
       ▼
Renderer       -- 按顺序准备状态并绘制物体
       │
       ├── Transform -- 物体位置、旋转、缩放和父子层级
       ├── Mesh      -- 顶点、索引和几何边界
       └── Material  -- Shader、颜色、纹理和表面渲染状态
```

- `Mesh`只负责几何数据，不知道物体使用哪一个Shader，也不保存材质颜色。
- `Material`只描述表面如何显示，不包含Mesh。多个物体可以共享同一个Mesh或Material。
- `SceneLighting`只保存场景级光源参数，不拥有Shader、Texture或其他GPU资源。
- `Renderer`把上述数据转换成OpenGL调用；`Scene`负责提供物体列表和场景更新顺序。
- 具体的展示Shader可以放在示例层。框架不会把某个示例的光照模型强行写进所有应用。

## 2. Shader能力分类

Shader是最终决定顶点如何变换、片段如何着色的对象。Renderer只按约定上传它能够识别的通用uniform，不会替Shader实现缺少的光照计算。

当前可以把Shader分为三类：

### Unlit Shader

不参与光照计算，通常只使用`model`、`view`、`projection`、`baseColor`和可选纹理。没有光照相关uniform时，Renderer上传的光照参数会被Shader忽略。

### 旧单方向光 Shader

通过下面的uniform描述一盏主方向光：

```text
lightDirection
lightColor
lightIntensity
ambientLight
```

这类Shader继续用于早期教学示例。它可以正常读取只有主灯的`SceneLighting`，但如果场景配置了额外方向光、点光源或聚光灯，Renderer会在绘制前抛出异常，而不是悄悄丢弃这些灯。

### 场景光照 Shader

声明`directionalLightCount`后，Shader会被视为支持当前的多光源接口。Renderer会继续上传：

- 最多2盏方向光，其中`directionalLights[0]`是主灯；
- 最多8盏点光源；
- 最多4盏聚光灯；
- 一个场景级`ambientLight`。

Shader必须自行决定如何使用这些数据。旧内置几何使用Lambert，新PBR使用GGX/Smith/Schlick；二者都接点光源距离衰减和聚光灯锥角衰减。

Renderer使用uniform是否存在来判断Shader能力。uniform被编译器优化掉时也会被视为不存在，因此自定义Shader需要实际使用声明的接口。

`Shader`缓存每个uniform名称的驱动查询结果，包括不存在的`-1`。缓存仅属于已链接的程序，移动Shader时随程序转移；没有跨程序共享或线程安全保证。当前没有重新链接入口，以后加入热重载时必须同步清空缓存。

## 3. Material约定

Material的职责是组合以下内容：

- 一个Shader；
- 一个线性空间中的基础颜色`baseColor`；
- 一个可选Texture；
- 可选PbrParameters及MR/法线/AO/发光四个纹理槽位；
- `RenderMode`和`CullMode`等表面绘制配置。

Material不拥有Mesh，也不负责从磁盘寻找资源。它有两种资源引用方式：

- 借用模式保存`Shader&`和`Texture*`，调用方必须保证资源在Material使用期间一直有效；
- `shared_ptr`持有模式，用于跨初始化作用域共享资源，但GPU资源仍必须在Window销毁前释放。

Material调用`use()`时会设置通用材质uniform：

```text
baseColor
hasTexture
textureSampler
```

没有纹理时会主动解绑0号纹理单元，并上传`hasTexture = false`，避免当前Shader采样到前一个物体遗留的纹理。自定义Shader也可以完全不使用纹理，只保留基础颜色。

`RenderMode`必须显式设置：

- `Opaque`：关闭混合并开启深度写入；
- `AlphaMask`：关闭混合并写深度，Shader按cutoff丢弃片段；
- `AlphaBlend`：开启普通非预乘Alpha混合，保留深度测试并关闭深度写入。

不能根据`baseColor.a`或图片是否带Alpha自动猜测渲染模式，因为不透明图片也可能带有Alpha通道。

`CullMode::Back`表示启用背面剔除，默认约定屏幕上逆时针三角形为正面；`CullMode::None`表示两面都绘制。平面和圆盘等开放几何体通常使用双面材质，闭合的立方体、球体和柱体通常可以使用背面剔除。

`correctMirroredWinding`用于负缩放场景。开启后，Renderer会根据物体的最终世界矩阵，包括父节点变换，决定使用`GL_CCW`还是`GL_CW`作为正面绕序。它只修正面剔除方向，不会修正错误的顶点顺序，也不会替代正确的法线变换。

## 4. 场景光照接口

`SceneLighting`属于Scene，不属于单个Material。光源目前使用世界空间坐标和方向：

- 主方向光：兼容旧的`DirectionalLight`接口；
- 额外方向光：最多1盏；
- 点光源：最多8盏，具有位置、颜色、强度和范围；
- 聚光灯：最多4盏，具有点光源参数、方向和内外锥角；
- 环境光：场景统一颜色，不会因为主灯强度为0而自动消失。

Renderer在开始绘制前会校验SceneLighting的数量、范围、角度和有限数值。超出限制会报错，不会静默截断。灯光当前不会自动绑定到GameObject，也不会随节点父子关系移动；应用层需要自己更新世界空间参数。

Renderer会在开始绘制前先校验所有RenderItem和Shader能力，再上传本批次的光照参数。这样配置错误不会只绘制半个场景。

## 5. 颜色空间和sRGB边界

颜色空间必须分清“纹理存储格式”和“Shader计算空间”：

- glTF基础颜色纹理和明确标记为sRGB的图片使用sRGB内部格式；
- 纹理采样后应在Shader中作为线性颜色参与光照计算；
- 基础颜色因子也应按线性空间参与漫反射计算；
- Shader如果自己把线性结果编码为sRGB，需要把Material的`shaderOutputsSrgb`设为`true`；
- Renderer发现该标记后，会临时关闭`GL_FRAMEBUFFER_SRGB`，避免再次编码；
- Renderer绘制结束后会恢复调用方进入绘制前的帧缓冲sRGB状态。

`shaderOutputsSrgb = false`表示Shader没有自行编码，Renderer沿用调用方的帧缓冲sRGB开关，不会自动开启它。调用方若选用硬件转换，须同时提供sRGB格式的颜色附件和开启转换；标记本身不会改变附件格式。两种编码路径只能选择一种。

早期RGBA8示例保留原行为。新Application配置`linearHdr=true`时在线性RGBA16F内光照/混合，最后Reinhard和一次sRGB编码；此路径拒绝已经手动编码的材质。不要把旧示例像素值直接当成HDR或色调映射参考。详细颜色、蒙皮及阴影接口见[PBR动画与阴影使用说明](PBR动画与阴影使用说明.md)。

## 6. Renderer的绘制规则

`Scene::render`最终会把对象交给`Renderer::drawItems`。该入口负责：

1. 检查Mesh、Material和Transform指针；
2. 校验场景光照和Shader能力；
3. 将物体分成不透明组和透明组；
4. 先绘制不透明物体；
5. 将透明物体按摄像机空间Z从远到近稳定排序；
6. 为每个材质应用深度、混合和面剔除配置；
7. 绘制完成或发生异常时恢复进入前的OpenGL状态。

不透明阶段使用深度测试和深度写入，关闭混合。透明阶段保留深度测试、关闭深度写入并开启普通非预乘Alpha混合。当前排序以对象的排序参考点为单位，适用于互不穿插的透明物体；相交透明网格、同一网格内部三角形排序和复杂折叠表面仍不保证正确。

Renderer会恢复深度测试、深度写入、混合、混合函数、面剔除、正面绕序、Shader程序、VAO、活动纹理单元和0号纹理绑定。它不会恢复Shader的uniform值，因为uniform属于Shader程序对象，而不是临时OpenGL状态。

低层`Renderer::draw`是显式的单物体入口，深度、混合、剔除、镜像绕序及sRGB开关由调用方管理，也不自动恢复程序和纹理绑定；需要自动应用Material配置和恢复状态时，应使用`Scene::render`或`Renderer::drawItems`。

每批绘制复用一份相机矩阵；每个RenderItem只计算一次世界矩阵和需要的法线矩阵，供校验、排序、镜像绕序和绘制共用。透明排序比较器只比较预先计算的深度。所有快照在函数返回时丢弃，下一帧修改Transform或父节点会立即生效；这不是跨帧场景变换缓存。

## 7. 当前不支持的内容

以下能力不应从当前接口推断出来：

- 完整glTF材质扩展模型（核心MR PBR已有）；
- IBL、环境探针和间接光照（直接光高光已有）；
- 点光/聚光阴影和级联阴影（主方向光Shadow Map已有）；
- 视差映射（法线贴图与切线空间已有）；
- 透明物体的逐三角形排序、加权混合或OIT；
- 光源自动绑定GameObject并参与父子Transform；
- Renderer自动合并draw call或自动实例化；
- 完整材质管线缓存（uniform位置缓存已有）。

这些功能以后可以在已有约定上扩展，但应先增加明确的数据结构、Shader接口和回归测试，不能仅通过在Renderer里继续添加条件分支来隐式实现。

## 8. 推荐使用方式

应用层创建物体时，把几何、材质和变换分别准备，再交给Scene：

```cpp
auto mesh = resources.loadMesh(meshPath);
auto material = resources.loadMaterial(materialPath);

auto &object = application.scene().createObject("模型");
object.setRenderable(mesh, material);
object.transform.position = {0.0f, 0.0f, 0.0f};

application.scene().lighting().mainLight().direction = {-0.5f, -1.0f, -0.3f};
```

应用层选择适合的Shader和光照配置；框架层负责资源生命周期、对象组织、排序、状态隔离和错误检查。这样示例可以尝试不同的视觉效果，而不会把某个示例的模型、灯光或Shader实现写死到基础渲染模块中。
