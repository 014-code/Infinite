# 音频系统说明

当前音频系统分成三层：

```text
AudioSystem
├── 音频设备和后端
├── AudioClip文件缓存
├── AudioVoice播放实例
└── Master / Music / Sfx / Ui / Ambient混音总线

GameObject
└── AudioSourceComponent（可选的持续场景音源）
```

底层使用MSYS2 UCRT64提供的miniaudio。miniaudio类型只出现在音频实现文件中，应用层只接触引擎自己的接口。
安装依赖：

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-miniaudio
```

## 播放一次性音效

短音效不需要挂到GameObject，直接从Application的AudioSystem播放：

```cpp
auto pickup = application.audio().loadClip(directory / "assets/pickup.wav");

AudioPlayOptions options;
options.bus = AudioBus::Sfx;
options.volume = 0.8f;
application.audio().play(pickup, options);
```

`AudioClip`是共享资源，`AudioVoiceId`是一次播放实例。相同路径和加载模式会命中Clip缓存，但每次play都可以有不同的音量、音高、循环和空间位置。

## 挂载持续音源

持续的火焰、瀑布或机器声音可以挂到GameObject：

```cpp
auto clip = application.audio().loadClip(directory / "assets/water.ogg",
    AudioClipOptions{AudioLoadMode::Streaming});

auto &object = application.scene().createObject("waterfall");
object.setAudioSource(application.audio(), clip);
object.audioSource().setBus(AudioBus::Ambient);
object.audioSource().setLooping(true);
object.audioSource().setSpatial(true);
object.audioSource().play();
```

`Scene`每帧会把带空间化音源的物体位置同步给AudioSystem。组件不负责销毁音频设备，只在自身销毁或解绑时停止当前Voice。

## 总线和暂停

总线音量不会修改单个Voice的原始音量：

```cpp
application.audio().setBusVolume(AudioBus::Music, 0.5f);
application.audio().setBusMuted(AudioBus::Sfx, true);
application.audio().setPaused(true);
```

`setPaused(true)`只暂停当前Voice，不清空Clip缓存；恢复时只恢复由全局暂停挂起的Voice，之前被应用单独暂停的Voice不会被误启动。

背景音乐目前可以通过 `AudioSystem::play` 使用 `AudioBus::Music` 和循环播放。专门的跨曲淡入淡出控制器（MusicPlayer）属于下一阶段，不应由每个GameObject自行实现。

## 生命周期和限制

- 音频接口和场景接口一样只在主线程调用；设备混音线程由miniaudio内部管理。
- `AudioVoiceId`在stop后立即失效，不能缓存成永久指针。
- Static适合短WAV音效，Streaming适合长OGG音乐。
- `AudioSystem`默认允许设备失败后降级为Null Backend；自动化测试因此不依赖声卡。
- 当前没有AudioSource序列化、音频事件表、动态资源热加载和复杂混音快照。
- 一次性跳跃、收集、按钮音效应直接调用AudioSystem，不要为每个短音效创建长期组件。

后续扩展顺序建议是：MusicPlayer淡入淡出、音频事件/音频资源配置、3D衰减参数、AudioSource序列化，最后再考虑更复杂的空间化和环境混响。
