# 项目功能清单

这是一份当前实现的导航，不是未来功能承诺。具体行为以对应接口和测试为准；新增或改变模块时应同步维护本表。

## 已实现的框架能力

| 模块 | 已有能力 / 源码入口 | 示例或测试 | 当前边界 |
| --- | --- | --- | --- |
| 应用运行 | `src/core/Application.h`：初始化、事件、更新、绘制、退出、异常清理、帧时间 | application_template / application、frame_timing测试 | 单次run、主线程、非固定步长物理循环 |
| 窗口 | `src/platform/Window.h`：OpenGL上下文、尺寸、焦点、最小化、VSync | window测试及各示例 | 只允许一个活动窗口 |
| 输入 | `src/input/`：键鼠状态、逐帧边沿、位移、滚轮、ActionMap | input_state、input_action测试 | 动作是键/按钮的OR组合；没有手柄和可编辑输入配置文件 |
| 摄像机 | `src/graphics/camera/Camera.h`：视图、透视和正交投影 | camera测试 / 多个3D示例 | 自由观察控制器在examples/common，不是角色或碰撞系统 |
| 变换 | `src/math/Transform.h`：位置、缩放、四元数、欧拉角便捷接口、父子世界变换；lighting模块提供法线矩阵 | transform、lighting测试 | 没有跨帧脏标记缓存；不能把任意剪切矩阵无损当成TRS |
| 场景 / 对象 | `src/scene/`：ID、增删查找、启用状态、更新回调、父子关系、Renderable | scene_objects / scene、scene_render测试 | 不是完整ECS；更新期间不能增删对象，引用受对象生命周期限制 |
| 网格 | `src/graphics/geometry/`：位置、RGBA颜色、UV、法线、切线，索引绘制与包围盒；蒙皮另有属性缓冲 | mesh_material、skin测试 | 没有动态编辑；蒙皮包围盒仍为绑定姿态 |
| 内置几何 | `Scene::createCube/Plane/Disk/Sphere/Cylinder/Cone`：尺寸、分段、网格缓存、独立默认材质 | primitive_shapes / primitive系列测试 | 不附带碰撞体，不是任意建模工具 |

| 光照 | Scene持有环境光、最多2方向光、8点光、4聚光；Lambert与GGX/Smith/Schlick PBR | scene_lighting、pbr_materials / lighting、pbr测试 | 灯不挂对象、不继承Transform、不存档；无IBL/间接光 |

| 阴影 | `graphics/rendering/shadows/`：主方向光深度贴图、3×3 PCF、MASK及蒙皮投影 | directional_shadow / directional_shadow测试 | 固定正交覆盖盒；BLEND不投影；无点光/聚光阴影和级联 |
| 文件资源 | `src/assets/`：OBJ、`.material`、glTF纯CPU解析；`ResourcePath`处理资源路径 | asset_scene、gltf_model / loader系列测试 | OBJ不读MTL；不是通用虚拟文件系统 |

| 动画 | `animation/`：只读Clip、TRS STEP/LINEAR、短路径四元数、独立Player、交叉淡入和轻量状态机 | node_animation / animation_sampler、animation_player测试 | 无CUBICSPLINE、倒放、分层混合、事件、根运动；不存档 |
| 蒙皮 | Skin、独立JOINTS/WEIGHTS缓冲、实例关节绑定、GPU位置/法线/切线变形 | skeletal_animation / skin、directional_shadow测试 | 每顶点4权重，最多64关节且受设备限制；无IK/重定向/双四元数 |
| 缓存 | `src/resources/`：文件Shader/Texture/Mesh/Material/Model缓存；PrimitiveResources缓存生成网格 | resource_manager、model_instance、primitive_scene测试 | 同步、主线程；没有自动淘汰、文件监控或热重载。共享Material的修改影响所有引用者 |
| 存档 | `SceneSerializer`：v4文本，兼容读取v1/2/3 | asset_scene / scene_serialization、scene_resource、primitive_serialization测试 | 见下节，不能保存任意运行状态 |
| 诊断 | `src/core/Log.h`、`OpenGLDebug`：分级同步日志、文件输出、GL错误检查 | log、opengl_debug测试 | 没有日志轮转；GL检查是错误消费点，不是驱动调试回调 |
| 工程与验证 | CMake Preset、资源同步、安装打包、CPU与真实像素回归、示例隐藏窗口冒烟 | CMakeLists.txt、scripts、tests | 本机测试不等于远端CI已通过；软件OpenGL不能替代真实驱动 |

## 存档究竟保存什么

保存：对象名称、active、局部TRS、父子索引、透明排序参考点、OBJ与`.material`路径，以及内置几何体的参数和默认颜色。

不保存：更新回调、相机、输入映射、灯光、glTF模型实例、没有可重建来源的临时Mesh/Material。不能重建的资源会报错，不会悄悄丢掉。加载成功替换对象集合，失败保留原对象；目标Scene已有的光照配置始终保留。

保存采用同目录独占临时文件，完成写入、刷新和关闭后才替换旧档；不会先截断或删除旧档。`scene_file`测试覆盖中断清理、失败替换与中文路径，不代表已验证断电、磁盘写满或网络文件系统。

## 示例与框架不要混淆

独立入口包含空模板及各阶段展示，完整名单见[README](../README.md#模块结构)。

- `player_controller`是示例层的移动命令、平地位移和跳跃，不是通用角色物理、碰撞或导航。
- 旧示例自动旋转来自update回调；新node_animation/skeletal_animation使用引擎动画片段与播放器，但尚无混合/状态机。
- `material_showcase`使用真实下载模型，但只展示基础颜色贴图与漫反射，不完整还原glTF材质。
- `primitive_shapes`调用引擎内置几何入口；形状生成属于框架，摆放布局与按键属于示例。

## 如何核实与回归

在项目根目录使用Preset；首次使用先把`E:/msys64/ucrt64/bin`加入当前终端PATH。

```powershell
cmake --build --preset msys2-ucrt64-debug
ctest --preset msys2-ucrt64-debug --show-only
ctest --preset msys2-ucrt64-debug -L cpu --output-on-failure
ctest --preset msys2-ucrt64-debug -L graphics --output-on-failure
```

测试数量随维护变化，以CTest实际登记列表为准。设计计划、历史验收次数与当前能力不是同一件事。
