# Infinite 引擎入门与使用教程

这是一份从零开始的完整教程：环境准备 → 构建运行 → 理解引擎 → 写第一个应用 → 逐模块使用（渲染/光照/模型/动画/物理/输入/组件/UI/游戏流程/音频/粒子/存档）→ 测试 → 交付 → 排查。

**三条阅读路径**

| 你的目的       | 建议顺序                                |
| ---------- | ----------------------------------- |
| 只想把它跑起来看看  | 第 1、2 章，然后照第 19 章附录 A 挑示例运行         |
| 想写自己的应用/游戏 | 第 1–7 章，再按需要跳到第 8–15 章              |
| 想改引擎本身     | 先读第 3 章（心智模型与铁律）、第 16 章（测试），其余按模块查阅 |

术语与边界以[项目功能清单](项目功能清单.md)为准；每个专题的细节文档见第 19 章附录 B。

## 1. 环境准备

### 1.1 安装工具链

项目固定使用 **MSYS2 UCRT64**，安装目录约定为 `E:\msys64`（不是则见 1.3）。

```bash
pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake \
  mingw-w64-ucrt-x86_64-ninja mingw-w64-ucrt-x86_64-glfw \
  mingw-w64-ucrt-x86_64-glew mingw-w64-ucrt-x86_64-glm mingw-w64-ucrt-x86_64-stb \
  mingw-w64-ucrt-x86_64-miniaudio
```

依赖使用 MSYS2 提供的 GLFW、GLEW、glm、stb、miniaudio 和仓库内 cgltf；字体加载复用 stb 包中的 stb_truetype，
没有额外引入完整UI框架或系统字体依赖。

### 1.2 必须把工具链加进 PATH（最容易踩的坑）

**任何编译命令之前**，先把 `E:\msys64\ucrt64\bin` 加到当前终端的 PATH：

```powershell
$env:PATH = 'E:\msys64\ucrt64\bin;' + $env:PATH      # PowerShell
```

```bash
export PATH="/e/msys64/ucrt64/bin:$PATH"              # Git Bash
```

**漏掉的症状很隐蔽**：编译器驱动能启动，但它调用的 `cc1plus.exe` 加载不到 `libmpfr-6.dll`，  
于是 **g++ 静默退出（返回码 1，没有任何错误输出）**，ninja 只报 `FAILED: [code=1]` 而看不到任何诊断信息。

> **排查口诀**：编译失败但一条错误信息都没有 → 先怀疑 PATH，而不是代码。

### 1.3 MSYS2 装在别处怎么办

Preset 假定 `E:\msys64`。装在别处时创建 `CMakeUserPresets.json`（已被 Git 忽略）继承 Preset 并覆盖环境变量 `INFINITE_UCRT64_ROOT`，不要直接改仓库里的 Preset。

## 2. 构建、运行与测试

### 2.1 三条命令

```powershell
cmake --preset msys2-ucrt64-debug     # 配置（首次或 CMakeLists 变更后）
cmake --build --preset msys2-ucrt64-debug
ctest --preset msys2-ucrt64-debug
```

Preset 固定了工具链并把编译并发限制为 **1**（防内存不足）。本机内存充裕时可以手动提速：

```bash
cmake --build build-ucrt64 --parallel 4
```

### 2.2 产物在哪里

构建结果全部落在 **`runtime/examples/<示例名>/`**，每个示例一个目录，里面有自己的 exe、shader、资源，以及一份运行库 DLL —— 双击即可运行，不需要配置 PATH：

```
runtime/examples/physics_demo/physics_demo.exe
runtime/examples/physics_demo/shaders/...
runtime/examples/physics_demo/logs/physics_demo.log   # 每次运行的日志
```

**资源同步是构建时的**：改 shader、图片、场景文件后重新构建即可同步到运行目录（因为资源被登记为独立构建依赖），不需要重新链接 exe。  
但**删除源码资源不会自动删除运行目录里的旧副本**，也不是运行中的热重载。

### 2.3 测试

```powershell
ctest --preset msys2-ucrt64-debug -L cpu       # 无窗口测试（不需要 GPU 上下文）
ctest --preset msys2-ucrt64-debug -L graphics  # 真实 OpenGL 测试（像素回归 + 示例冒烟）
ctest --preset msys2-ucrt64-debug -N           # 只列出，不执行
```

测试数量会随着模块和示例增加而变化，不在教程里写死。使用 `ctest --preset msys2-ucrt64-debug -N` 查看当前登记数量；测试按 `cpu` 和 `graphics` 标签区分。状态、UI、音频、粒子、存档、SceneManager、Area 和字体回归都通过 CTest 登记，示例则统一支持 `--smoke-test`：创建隐藏窗口、运行三帧并检查画面。

## 3. 引擎心智模型

### 3.1 模块职责

```
src/
├── core/        Application 运行层、帧时间、日志、资源路径
├── game/        ApplicationStateStack、菜单状态与状态切换策略
├── platform/    Window 与 OpenGL 上下文
├── input/       键鼠状态、边沿、ActionMap
├── math/        Transform（位置/缩放/四元数 + 父子层级）
├── scene/       Scene、GameObject、组件、SceneManager、内置几何体与场景序列化
├── ui/          UiCanvas、面板、标签、按钮、焦点输入与字体/文字排版
├── audio/       AudioSystem、Clip、Voice、MusicPlayer 与音频事件队列
├── particles/   CPU 粒子发射、生命周期、颜色和尺寸渐变
├── save/        跨关卡 SaveGame 数据与场景原子保存
├── graphics/    camera / lighting / materials / geometry / rendering / resources / shaders
├── assets/      OBJ、.material、glTF 的纯 CPU 解析
├── animation/   Clip、采样、播放器、混合、蒙皮
├── resources/   Shader/Texture/Mesh/Material/Model 缓存
└── physics/     碰撞形状、AABB/射线、碰撞世界、角色控制器、刚体
```

分层规则：**`physics` 只依赖 `glm` 和 `src/math/`**，`assets` 不做 GPU 操作，`scene` 组合渲染/物理/音频组件但不拥有外部服务，`game` 和 `ui` 负责应用流程与表现，示例层不反向进入引擎库。音频、粒子和存档保持独立，应用可以按需使用，不会因为创建一个普通场景而自动打开设备或生成粒子。

### 3.2 一帧的执行顺序

```
pollEvents                  → 收集窗口输入，刷新按键边沿和鼠标增量
state.commitPending         → 在安全边界提交 Push/Pop/Replace/Clear/Quit
state.onEvents              → 当前应用状态处理菜单、暂停和窗口事件
timing.advance              → 计算可变帧 dt（首帧为 0，普通帧有上限）
state.update / app.update   → 应用逻辑、输入、SceneManager请求、动画与粒子
fixed physics steps         → 同步静态体、推进物理、同步动态体、派发 Area 进入/离开事件
state.afterPhysics          → 读取物理结果，准备摄像机或游戏规则
scene.update(dt)            → 按创建顺序执行 active GameObject 的脚本更新
audio.update(dt)            → 推进 Voice、MusicPlayer 和音频事件；不放进固定物理步
clear + scene.render        → 清颜色/深度，绘制不透明和透明物体
ui.processInput + ui.render → 处理焦点/鼠标命中并绘制最小 UI
state.afterRender           → 截图、像素检查或提交下一次流程操作
swapBuffers
```

状态栈会根据栈顶 `StateFramePolicy` 决定是否更新 Scene、模拟物理、绘制场景和更新音频；暂停状态通常停止前两项但保留 UI 和输入。固定物理步骤可能一帧执行多次，角色移动和动态刚体同步必须放在固定阶段；音频每帧更新一次。动画采样、脚本和粒子属于可变帧逻辑。物理、动画和应用代码都可能影响 Transform，但**一个节点在同一阶段只能有一个明确的写入者**。

### 3.3 五条铁律（违反会得到悬空或双重释放）

1. **先销毁 Scene，再销毁 GPU 资源，最后关闭 Window**。`Application` 的成员顺序已经保证这一点，自己写循环时要手动保证。
2. **借用 vs 持有**：`setRenderable(const Mesh&, const Material&)` / `setPhysicsBody(world, shape)` 是**借用**，被借对象必须活得更久；跨作用域请用 `shared_ptr` 重载。
3. **`PhysicsWorld` 必须比 `Scene` 活得更久**（物体析构时会向世界注销句柄）。示例在 `main` 里用 `shared_ptr` 持有世界，让它在 `Application` 之后释放。
4. **更新期间不能增删物体**（`Scene::update` 回调里禁止 create/remove/clear 和重入 update）。
5. **长时间保存用 ID，不要保存引用/指针**：增删对象会使引用失效，用 `Scene::findObject(id)` 重新取。
6. **状态切换和关卡切换要排队**：在状态回调或 Scene 更新中调用 `push`、`replace`、`requestLoad` 只提交请求，由安全边界统一执行。
7. **音频句柄和组件是主线程接口**：`AudioVoiceId` 在 stop 后立即失效；一次性音效用 `AudioSystem`/事件队列，跟随物体的持续声音才用 `AudioSourceComponent`。
8. **UI 回调不能继续使用已重建的控件指针**：按钮可以清空或重建 `UiCanvas`，回调返回后重新查找控件。

## 4. 第一个应用

引擎推荐入口是 `Application`：它负责事件、时间、清屏、Scene 更新与绘制、交换缓冲，你只写回调。

```cpp
#include "common/ExampleRun.h"   // 示例层样板：日志、Escape、冒烟测试

int main(int argc, char *argv[])
{
    return runExample(argc, argv, "my_app", "My App",
        glm::vec4(0.05f, 0.06f, 0.09f, 1.0f),                      // 清屏色
        [](Application &application, const std::filesystem::path &directory)
        {
            // initialize：GL 上下文已就绪，在这里创建 Shader/Mesh/Material/物体。
            LOG_INFO("my_app ready");
        },
        ExampleFrameContent::DrawnScene,                            // 冒烟测试期望画面非空
        [](Application &application, float deltaTime)
        {
            // update：每帧调用一次，dt 已做暂停与上限处理。
        });
}
```

回调全部可选，不需要继承任何基类：

| 回调            | 时机                 | 典型用途                   |
| ------------- | ------------------ | ---------------------- |
| `initialize`  | 上下文就绪、计时开始前        | 加载资源、创建场景内容            |
| `onEvents`    | 事件收集后（暂停时也调用）      | 退出、窗口级操作；**不要**依赖本轮 dt |
| `update`      | `Scene::update` 之前 | 输入、物理、动画、增删物体          |
| `afterRender` | 绘制后、交换缓冲前          | 截图、像素校验                |

如果应用有主菜单、暂停和结算流程，可以额外创建 `ApplicationStateStack`，使用 `application.run(states)`：状态对象由状态栈拥有，状态回调里的 `push/pop/replace/clear/quit` 会排队到安全边界执行。简单示例仍可直接使用 `runExample` 的单状态入口。

不要把 `application_template/main.cpp` 里的三角形逻辑塞回引擎：**模板只显示空白背景**，需要内容就自己创建物体。

要点：

- 初始化和每帧都在**主线程**；
- `Application` 只能 `run` 一次；
- 暂停/恢复的首帧 `dt` 为 0，普通帧 `dt` 上限 0.1 秒（`ApplicationConfig::maximumDeltaTime`）；
- 真实时间用 `frameTime().realDeltaTime`，模拟时间用传入的 dt / `frameTime().simulationTime`；
- `ApplicationConfig::uiFontPath` 可以指定 TTF/OTF 字体；留空时 UI 使用内置英文 5×7 位图字体。

## 5. 画第一个物体

内置几何体让你不写顶点数据就能开始：

```cpp
CubeOptions options;
options.name = "cube";
options.color = glm::vec4(0.85f, 0.45f, 0.3f, 1.0f);
GameObject &cube = application.scene().createCube(options);
cube.transform.position = glm::vec3(0.0f, 0.5f, 0.0f);
cube.transform.setEulerAngles(glm::vec3(0.2f, 0.6f, 0.0f));

// 让物体自己转：运动逻辑注册到物体，不要把主循环写进框架。
cube.script().setUpdateCallback([](GameObject &self, float deltaTime)
{
    self.transform.rotateEuler(glm::vec3(0.0f, deltaTime, 0.0f));
});

// 相机：位置、目标、上方向；投影每帧按窗口实际帧缓冲比例生成。
application.camera().setView(glm::vec3(0.0f, 2.0f, 5.0f), glm::vec3(0.0f, 0.5f, 0.0f), glm::vec3(0.0f, 1.0f, 0.0f));
application.camera().setPerspective(glm::radians(60.0f), 0.1f, 100.0f);
```

六种内置形状：`createCube / createPlane / createDisk / createSphere / createCylinder / createCone`（统一入口 `createPrimitive`）。  
每种都有自己的 Options 结构（尺寸、分段数、颜色、名字、自定义材质）。

**边界**：内置几何体不带碰撞体，也不是建模工具；形状生成属于框架，摆放布局属于你的应用。

## 6. 场景、物体与变换

```cpp
Scene &scene = application.scene();
GameObject &object = scene.createObject("角色");
const ObjectId id = object.id();            // 1 起步、0 无效、删除后不复用

// 父子层级：父节点的世界变换会传递到子节点
GameObject &weapon = scene.createObject("武器");
weapon.transform.setParent(&object.transform);
weapon.transform.position = glm::vec3(0.5f, 0.2f, 0.0f);

// 长期保存的是 ID，不是引用
if (GameObject *found = scene.findObject(id)) { found->setActive(true); }
scene.removeObject(id);                     // 此后 object 引用失效
```

`Transform` 同时有位置、缩放、四元数旋转，以及欧拉角便捷接口（内部始终只保存四元数，避免两份状态不同步）。**没有跨帧脏标记缓存**：每次 `worldMatrix()` 都重算父链，层级很深时注意。

组件化：`GameObject` 现在把职责拆成多个始终存在、按需激活的组件。组件不单独拥有物体身份和 `Transform`，`GameObject` 仍负责名称、ID、层级和 active 状态；组件负责各自的资源绑定、生命周期和同步规则：

```cpp
object.setRenderable(sharedMesh, sharedMaterial);   // 持有模式，推荐跨作用域使用
object.setSortOrigin(glm::vec3(0.0f, 1.0f, 0.0f));  // 透明排序参考点，默认局部原点

// 脚本组件：只保存应用层C++回调，不把具体玩法写进引擎。
object.script().setUpdateCallback([](GameObject &self, float deltaTime)
{
    self.transform.rotateEuler(glm::vec3(0.0f, deltaTime, 0.0f));
});

// 静态/动态物理组件：物理世界必须比Scene活得更久。
object.setPhysicsBody(world, CollisionShape(BoxShape(glm::vec3(1.0f))));
object.setDynamicPhysicsBody(world, CollisionShape(SphereShape(0.5f)));

// 角色组件不接管输入；应用在fixedUpdate中写速度并调用move。
object.setCharacterBody(world);

// Area是查询区域，不参与碰撞响应，只产生进入/离开事件。
object.setArea(world, CollisionShape(SphereShape(2.0f)));
object.area().setBodyEnteredCallback([](PhysicsBodyId bodyId)
{
    LOG_INFO("body entered area " + std::to_string(bodyId));
});
```

组件生命周期由 `GameObject` 管理。删除物体时，静态物理体、音频 Voice 和 Area 监听关系会先注销；组件析构不会删除共享资源。`Renderable`、`PhysicsBodyComponent`、`CharacterBodyComponent`、`AreaComponent` 和 `AudioSourceComponent` 是当前内置组件，`ScriptComponent` 是应用逻辑入口；目前没有反射、编辑器属性面板或运行时动态注册任意 C++ 组件。

Scene 的物理同步顺序是：静态体从 Transform 同步 → PhysicsWorld 固定步 → 动态刚体/角色写回 Transform → Area 计算进入/离开集合 → 渲染和音频读取最终状态。动态刚体由物理世界拥有位姿写入权，角色只由控制器写位置，应用不要在同一固定步再次覆盖它们。

## 7. 资源、着色器与材质

### 7.1 缓存语义

`ResourceManager` 按**规范化绝对路径**（Texture 还含加载选项）缓存，重复加载返回同一个 `shared_ptr`：

```cpp
ResourceManager &resources = application.resources();
auto shader   = resources.loadShader(directory / "shaders/my.vert", directory / "shaders/my.frag");
auto texture  = resources.loadTexture(directory / "textures/checker.png");
auto mesh     = resources.loadMesh(directory / "assets/cube.obj");
auto material = resources.loadMaterial(directory / "materials/checker.material");
```

**边界**：同步、主线程、无自动淘汰、无文件监控、无热重载；`clear()` 不会销毁仍被 Scene/材质持有的资源。

### 7.2 自定义材质

```cpp
auto material = std::make_shared<Material>(shader, glm::vec4(1.0f), texture);
material->setRenderMode(RenderMode::Opaque);   // Opaque / AlphaBlend / AlphaMask
material->setCullMode(CullMode::Back);         // 逆时针绕序为正面
material->setCorrectMirroredWinding(true);     // 单轴负缩放时自动修正正面绕序
object.setRenderable(mesh, material);
```

Shader 可约定的 uniform：`model`、`view`、`projection`、`baseColor`、`hasTexture`、`textureSampler`。  
**没有纹理时框架会把 `hasTexture` 设为 false 并解绑 0 号纹理**，避免采样到上一个物体残留的纹理 —— 自定义 Shader 要么处理这个开关，要么干脆不采样纹理。

### 7.3 透明度与排序

- 透明表面必须**显式**声明 `RenderMode::AlphaBlend`，不要靠纹理是否有 alpha 通道猜；
- 绘制顺序：不透明组（深度测试+写入、混合关闭）→ 透明组（深度测试保留、写入关闭、按视空间 Z **远到近**稳定排序）；
- 排序参考点是**物体级**的：相交的透明网格需要更细的逐三角形策略（当前不支持）；
- 绘制结束后框架会恢复进入时的深度/混合/剔除状态、程序、VAO、活动纹理单元与 0 号纹理绑定，**但不恢复 Shader 的 uniform 内容**。

## 8. 光照、PBR 与颜色空间

```cpp
SceneLighting &lighting = application.scene().lighting();
lighting.mainLight().direction = glm::vec3(-0.4f, -1.0f, -0.35f);   // 光线传播方向
lighting.mainLight().intensity = 1.2f;
lighting.ambient() = glm::vec3(0.25f);

PointLight point;
point.position = glm::vec3(2.0f, 2.0f, 0.0f);
point.color = glm::vec3(1.0f, 0.8f, 0.6f);
point.intensity = 4.0f;
point.range = 8.0f;
lighting.pointLights.push_back(point);      // 上限 8；另有聚光 4、方向光 2（含主灯）
```

**边界**：灯不是 GameObject 组件、不继承 Transform、不写入存档；没有 IBL 与间接光。

PBR 与 HDR（金属度/粗糙度工作流）：

```cpp
ApplicationConfig config;
config.linearHdr = true;        // 线性浮点渲染 + Reinhard 色调映射 + 一次 sRGB 输出
config.exposure = 1.0f;

PbrParameters parameters;       // 金属度/粗糙度/法线/AO/发光等，见 PbrParameters.h
material->setPbrParameters(parameters);

// 方向光阴影：需要 linearHdr + PBR 材质；可在运行时通过访问器开关
DirectionalShadowSettings shadow;
shadow.center = glm::vec3(0.0f); shadow.halfExtent = 8.0f;
shadow.distance = 15.0f; shadow.bias = 0.001f;
application.directionalShadow() = shadow;
```

颜色空间约定：颜色/发光贴图按 **sRGB** 读入，金属度/粗糙度/法线/AO 按**线性数据**读入；线性光照在浮点缓冲里做，最后统一输出编码 —— 旧 Shader 自己编码 sRGB 时必须声明 `setShaderOutputsSrgb(true)`，否则会二次编码。

## 9. 加载外部模型

```cpp
// A. 预览入口：用自己的 Shader，适合快速看形状与基础颜色贴图
auto model = application.resources().loadModel(
    directory / "assets/showcase.glb",
    directory / "shaders/preview.vert",
    directory / "shaders/preview.frag");

// B. 核心 PBR 入口：使用引擎内置线性 Shader，配 linearHdr = true
auto pbrModel = application.resources().loadPbrModel(directory / "assets/Avocado.glb");

// 把模型实例化进场景：返回根物体与全部节点/物体 ID
ModelInstance instance = ModelInstantiator::instantiate(application.scene(), *model, "avocado");
// ...使用结束后
ModelInstantiator::remove(application.scene(), instance);
```

支持范围：多节点、多 primitive、多材质、外部与内嵌资源、UV0、基础颜色/金属粗糙度/法线/AO/发光贴图、OPAQUE/MASK/BLEND、`KHR_materials_unlit`，以及 TRS 节点动画与蒙皮。

**不支持**（会显式诊断，不会静默忽略）：Morph Target、Draco/Meshopt 压缩、CUBICSPLINE 插值、未知必需扩展。  
OBJ 走 `loadMesh`，**不读 MTL**；材质请用 `.material` 文件。

## 10. 动画与蒙皮

流程：模型自带 `AnimationClip`（`model->animations()`），实例化进场景后由 `AnimationPlayer` 驱动：

```cpp
auto model = application.resources().loadModel(path, vsPath, fsPath);
ModelInstance instance = ModelInstantiator::instantiate(scene, *model, "character");

auto player = std::make_shared<AnimationPlayer>();
player->setLooping(true);
player->play(scene, 0);                       // 播放第 0 个片段
// player->crossFade(scene, 1, 0.3f);         // 交叉淡入到第 1 个片段
// player->setSpeed(1.5f);  player->pause();  player->setLooping(false);

// 每帧在 update 回调里推进；播放器只修改被它绑定的节点。
player->update(scene, deltaTime);
```

`update` 用 `shared_ptr` 捕获播放器，让它跨帧存活；每个实例用各自的播放器才能有独立进度。

动画片段还可以携带轻量事件标记。动画模块只报告事件名，具体播放音效、发射粒子或改变游戏状态由应用回调决定：

```cpp
player->setEventCallback([&application](const AnimationEvent &event)
{
    if (event.name == "footstep")
    {
        application.audioEvents().playOneShot(footstepClip);
    }
});
```

事件按时间从旧位置推进到新位置时触发；循环播放跨过片段末尾时也会正确处理时间段。事件不携带系统指针，避免动画资源反向拥有音频或粒子系统。

**边界**：无 CUBICSPLINE、无倒放、无分层混合、无根运动自动接管；动画状态不写入存档。
骨骼动画另见 `skeletal_animation` 示例与[PBR动画与阴影使用说明](PBR动画与阴影使用说明.md)。

## 11. 物理

物理世界的生命周期规则最容易出错：**在 `main` 里创建，比 `Application` 活得更久**。

```cpp
auto world = std::make_shared<PhysicsWorld>();
world->setGravity(glm::vec3(0.0f, -9.81f, 0.0f));

return runExample(argc, argv, "my_physics", "My Physics", clearColor,
    [world](Application &application, const std::filesystem::path &)
    {
        Scene &scene = application.scene();

        // 静态世界几何：直接注册到世界。平面用点法式描述。
        PhysicsFilter terrain;
        terrain.layer = PhysicsLayers::Terrain;
        world->createStaticBody(CollisionShape(PlaneShape(glm::vec3(0.0f, 1.0f, 0.0f), 0.0f)),
            glm::vec3(0.0f), glm::quat(1, 0, 0, 0), terrain);

        // 也可以让物体自己登记：删除物体时自动注销
        GameObject &wall = scene.createCube({});
        wall.transform.position = glm::vec3(3.0f, 1.0f, 0.0f);
        wall.setPhysicsBody(*world, CollisionShape(BoxShape(glm::vec3(1.0f))));

        // 动态刚体（首版仅球体）
        RigidBodySettings settings;
        settings.restitution = 0.4f;
        world->createDynamicBody(CollisionShape(SphereShape(0.3f)), glm::vec3(0.0f, 4.0f, 0.0f), settings);
    },
    ExampleFrameContent::DrawnScene,
    [world](Application &application, float deltaTime)
    {
        world->step(deltaTime);   // 固定步长推进：默认 1/60，单帧最多补 4 步
        // 渲染时用插值位姿，消除固定步长与帧率不一致的台阶感
        // world->interpolatedBodyState(bodyId, world->interpolationAlpha())
    });
```

查询（同步、不修改世界状态）：

```cpp
if (auto hit = world->raycast(Ray(origin, direction), 60.0f))
{
    placeAt(hit->hit.point + hit->hit.normal * 0.01f);   // 法线朝射线来向，可直接用于摆放在表面
    LOG_INFO("hit distance " + std::to_string(hit->hit.t));
}
for (const auto &overlap : world->overlapShape(shape, position, rotation))
{
    position += overlap.pushOutNormal * overlap.contact.penetration;   // 把查询形状移出该体
}
```

角色控制器：调用方决定重力与跳跃，控制器只做碰撞与移动。

```cpp
CharacterSettings settings;      // radius / cylinderHeight / skinWidth / 最大坡度 / 子步与滑动次数
CharacterController controller(settings);
CharacterState state;            // position / velocity / grounded / groundNormal
state.velocity.y += world->gravity().y * deltaTime;
if (state.grounded && jumpPressed) { state.velocity.y = jumpSpeed; }
state = controller.move(*world, state, deltaTime);
```

碰撞层/掩码：**双方掩码都要包含对方层**才算碰撞；查询用 `queryMask` 只筛选对方层。

```cpp
PhysicsFilter prop;
prop.layer = PhysicsLayers::Prop;     // 我在哪些层
prop.mask  = PhysicsLayers::Terrain | PhysicsLayers::Prop;   // 我愿意与哪些层碰撞
```

### 11.1 Trigger / Area 事件

`AreaComponent` 是查询区域，不会像刚体一样挡住、推动或响应其他物体。它在固定物理步完成后查询重叠集合，用前后集合差派发 `bodyEntered` 和 `bodyExited`：

```cpp
GameObject &pickupArea = scene.createObject("pickup_area");
pickupArea.setArea(*world, CollisionShape(SphereShape(1.5f)), PhysicsLayers::Prop);
pickupArea.area().setBodyEnteredCallback([&](PhysicsBodyId body)
{
    // 这里只记录游戏规则；如果要删物体，请在回调返回后执行。
    collectedBodies.insert(body);
});
pickupArea.area().setBodyExitedCallback([](PhysicsBodyId body)
{
    LOG_DEBUG("body exited area " + std::to_string(body));
});
```

Area 只识别 `PhysicsWorld` 中已有的碰撞体，`queryMask` 只筛选对方层；它不替代碰撞响应，也不提供节点名称或 GameObject 自动查找。回调中不要直接清空 Scene 或重入物理世界。

**边界**（详见[物理系统说明](物理系统说明.md)）：动态体首版仅球体、接触不产生力矩、无 CCD、无关节与软体、  
角色不推动刚体、物理体不写入场景存档。诊断值 `world->lastNarrowphasePairCount()` 可确认剪枝是否生效。

## 12. 输入

```cpp
const Input &input = application.input();

const bool holding  = input.isKeyDown(Key::W);        // 持续按住
const bool pressed  = input.wasKeyPressed(Key::Space);// 本帧刚按下（边沿）
const bool released = input.wasKeyReleased(Key::Space);
const glm::dvec2 delta = input.mouseDelta();          // 本帧位移增量
const bool looking  = input.isMouseButtonDown(MouseButton::Right);

动作映射把多个键合成一个语义动作（OR 语义）：

ActionMap &actions = application.actions();
actions.createAction("jump");
actions.bindKey("jump", Key::Space);
if (actions.wasPressed("jump", input)) { jump(); }
```

```cpp
const glm::vec3 viewDirection = target - camera.position();
const glm::vec3 direction = cameraRelativeDirection(viewDirection, forwardInput, rightInput);
// 约定：屏幕右方 = cross(viewDirection, up)；写成 cross(up, viewDirection) 会左右颠倒。
```

## 13. UI、游戏状态与关卡流程

### 13.1 最小 UI 与字体

UI 使用窗口逻辑像素布局，`UiCanvas` 拥有控件树和焦点，`UiRenderer` 集中负责 GPU 绘制。面板、标签和按钮不会直接调用 OpenGL，因此布局、命中测试和键盘焦点可以在无窗口测试中验证：

```cpp
UiCanvas &ui = application.ui();

UiPanel &panel = ui.create<UiPanel>();
panel.setRect({40.0f, 40.0f, 360.0f, 220.0f});

UiLabel &title = panel.createChild<UiLabel>("Infinite Demo");
title.setRect({24.0f, 20.0f, 300.0f, 40.0f});
title.setScale(3.0f);

UiButton &start = panel.createChild<UiButton>("Start");
start.setRect({24.0f, 90.0f, 300.0f, 48.0f});
start.setOnActivated([&application]
{
    application.sceneManager().requestLoad("level_1");
});
```

按钮支持鼠标命中、Tab/方向键焦点和 Enter/Space 激活；UI 回调可以请求状态或关卡切换，但实际切换仍在安全边界执行。坐标原点在窗口左上角，高 DPI 窗口由 `UiRenderer` 负责换算到实际帧缓冲尺寸。

默认字体是内置英文 5×7 位图，适合保证示例零资源运行。需要中文或其他 UTF-8 字符时，在创建 `Application` 前配置 TTF/OTF：

```cpp
ApplicationConfig config;
config.uiFontPath = directory / "fonts/NotoSans-Regular.ttf";
Application application(config);
```

字体文件由 `FontFile` 读取，`FontCollection` 负责 UTF-8 字符到字形，`FontAtlas` 把字形栅格化为 GPU 图集，`TextLayout` 负责换行、对齐和混排。当前仍是轻量 UI：没有自动布局、富文本、滚动容器、编辑框、中文字体随程序自动打包或字体回退链；发布时要把指定字体和 DLL 一起放进运行目录。

### 13.2 GameStateStack 与菜单

状态栈适合表达“主菜单 → 游戏中 → 暂停 → 结算”的应用流程。状态对象由 `ApplicationStateStack` 独占，状态回调中不能立即销毁自己：

```cpp
class GameplayState final : public ApplicationState
{
public:
    void onEvents(ApplicationStateContext &context) override
    {
        if (context.application().input().wasKeyPressed(Key::Escape))
        {
            context.states().push<PauseState>(); // 下一安全边界执行
        }
    }

    void fixedUpdate(ApplicationStateContext &context, float fixedDeltaTime) override
    {
        // 只消费已经在update阶段采样好的输入指令。
        (void)context;
        (void)fixedDeltaTime;
    }

    StateFramePolicy framePolicy() const noexcept override
    {
        return {}; // 游戏中更新Scene、物理、场景绘制和音频
    }
};

ApplicationStateStack states;
states.push<MainMenuState>();
application.run(states);
```

暂停状态通常把 `updateScene` 和 `simulatePhysics` 设为 `false`，保留 UI、事件和场景绘制；是否暂停音频由 `updateAudio` 以及状态进入/退出逻辑决定。`MainMenuState`、`PauseState`、`ResultState` 提供常用菜单按钮布局，但按钮动作、关卡内容和游戏数据仍由应用传入。对应的完整流程示例是 `menu_demo`。

### 13.3 SceneManager 与关卡切换

`SceneManager` 是应用层的同步关卡注册表，不负责后台加载或跨线程资源流：

```cpp
application.sceneManager().registerScene("level_1",
    [](Scene &scene, ResourceManager &resources)
    {
        auto mesh = resources.loadMesh("assets/level.obj");
        auto material = resources.loadMaterial("materials/level.material");
        GameObject &level = scene.createObject("level");
        level.setRenderable(mesh, material);
    });

application.sceneManager().requestLoad("level_1");
// Application在下一帧事件阶段自动commitPending()。
```

切换时先清空当前 Scene，再执行目标 Loader；Loader 抛异常时会清理半成品并保持空场景，不留下两个关卡混合的状态。需要立即切换时可调用 `load`，但只能在事件阶段或状态切换提交等安全边界使用。当前不包含异步加载、加载进度、场景栈和自动保存；复杂游戏应由状态栈协调“保存 → 卸载 → 加载 → 恢复”。

## 14. 音频与粒子

### 14.1 音频、音乐和 AudioSource

`AudioSystem` 负责设备、Clip 缓存、播放 Voice 和总线；`MusicPlayer` 负责当前音乐与交叉淡入淡出；`AudioEventQueue` 是动画、状态和游戏规则向音频系统发送窄事件的入口：

```cpp
auto click = application.audio().loadClip(
    directory / "audio/click.wav");

AudioPlayOptions options;
options.bus = AudioBus::Ui;
options.volume = 0.8f;
application.audioEvents().playOneShot(click, options);

auto music = application.audio().loadClip(
    directory / "audio/level.ogg",
    AudioClipOptions{AudioLoadMode::Streaming});
application.music().play(music, {AudioBus::Music, 0.7f, 1.0f, true}, 1.0f);
```

跟随场景物体移动的持续声音才使用组件：

```cpp
GameObject &waterfall = application.scene().createObject("waterfall");
waterfall.setAudioSource(application.audio(), loopClip);
waterfall.audioSource().setLooping(true);
waterfall.audioSource().setSpatial(true);
waterfall.audioSource().play();
```

一次性音效不需要创建 `AudioSourceComponent`。所有公开音频接口都在主线程调用；设备打开失败时默认降级到 Null Backend，因此没有声卡时游戏和 CPU 测试仍可启动。音频不会参与固定物理步，空间音源的位置由 `Scene::syncAudio()` 每帧从物体 Transform 同步。当前没有完整音频资源导入器、3D 衰减曲线、混响和编辑器总线面板。

### 14.2 CPU 粒子系统

`ParticleSystem` 当前提供可测试的 CPU 发射和生命周期模拟：粒子有位置、速度、生命周期、颜色渐变和尺寸渐变，适合先承载火花、烟雾等应用层规则：

```cpp
ParticleEmitterSettings settings;
settings.maxParticles = 512;
settings.emissionRate = 80.0f;
settings.lifetime = 0.8f;
settings.acceleration = glm::vec3(0.0f, -3.0f, 0.0f);

ParticleSystem sparks(settings);
sparks.setOrigin(glm::vec3(0.0f, 1.0f, 0.0f));
sparks.update(deltaTime);

for (const Particle &particle : sparks.particles())
{
    // 应用层把粒子转换成自己的 billboard/实例化绘制数据。
    drawParticle(particle);
}
```

它不是 GameObject 的默认组件，也不会自动注册到 Renderer；应用可以把 `particles()` 转换为点精灵、四边形或实例化网格。当前没有 GPU 粒子、碰撞、贴图动画、排序和粒子编辑器，这些应在明确渲染接口后再扩展。

## 15. 存档

```cpp
SceneSerializer::save(application.scene(), directory / "scenes/level.scene");
const std::vector<ObjectId> loaded = SceneSerializer::load(application.scene(), path);
```

**保存**：物体名称、启用状态、局部 TRS、父子索引、透明排序参考点、Mesh/Material 相对路径、内置几何体的生成参数与默认颜色。  
**不保存**：更新回调、相机、输入映射、灯光、glTF 实例、没有可重建来源的临时 Mesh/Material、物理体。  
不能重建的资源会**明确报错**，不会悄悄丢数据。

写入策略：先写同目录独占临时文件，完成刷新与关闭后才替换旧档；失败不截断旧档。格式为版本 4 的可读文本，**兼容读取 v1–v3**。

## 16. 日志与 GL 诊断

```cpp
#include "core/Log.h"

LOG_INFO("资源加载完成");
LOG_WARN("日志文件不可用，继续使用控制台");
LOG_ERROR("资源加载失败");
Log::setLevel(Log::Level::Debug);   // 需要看调试信息时降低阈值
```

每条记录含本地时间、级别、文件名与行号；输出到 stderr，可 `Log::setFile(path)` 追加写文件。示例统一把日志写到 exe 同级的 `logs/<名字>.log`。

GL 错误检查（需要当前线程有有效上下文）：

```cpp
INFINITE_GL_CHECK("资源初始化");
// ...一帧绘制...
INFINITE_GL_CHECK("本帧绘制");
```

它基于 OpenGL 3.3 的 `glGetError`，**会消费掉待处理错误**，记录的源码位置是检查点，不一定就是出错的那条指令。  
`NDEBUG` 构建会移除宏检查；需要强制检查时显式调用 `OpenGLDebug::checkErrors("区间", __FILE__, __LINE__)`。

**Shader 编译/链接失败不会表现为 `glGetError`**：它抛异常，异常信息里带源文件路径与驱动详情，由应用入口统一 `LOG_ERROR`。

## 17. 写测试

引擎不引入第三方测试框架，用 `tests/TestSupport.h` 的最小断言：

```cpp
#include "TestSupport.h"

int main()
{
    try
    {
        require(condition, "描述失败的期望");
        expectThrow<std::invalid_argument>([] { doSomethingIllegal(); }, "非法输入未被拒绝");
        std::cout << "my_test passed\n";
        return 0;
    }
    catch (const std::exception &error)
    {
        std::cerr << "my_test failed: " << error.what() << '\n';
        return 1;
    }
}
```

新增测试需要改 **两处**（登记 + 打标签）：

1. `cmake/EngineTests.cmake` 里加目标：
   ```cmake
   add_executable(infinite_my_test tests/my_test.cpp)
   configure_engine_test(infinite_my_test)
   ```
2. 若是**不创建窗口**的测试，把它加进文件末尾 `LABELS "cpu"` 的列表（否则默认归 `graphics`）。

示例测试直接编译示例源码，避免"测试与示例逐渐偏离"（如 `player_controller_test` 编译 `FlatGroundMovement.cpp`）。示例冒烟测试统一用 `--smoke-test` 走隐藏窗口三帧。

## 19. 常见问题速查

| 症状                                            | 原因                                                                    | 处理                                                               |
| --------------------------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 编译失败但**没有任何错误信息**，ninja 只报 `FAILED: [code=1]` | PATH 缺 `E:\msys64\ucrt64\bin`，`cc1plus.exe` 加载不到 `libmpfr-6.dll`，静默退出 | 按 1.2 设置 PATH 重新构建                                               |
| 改 shader/图片后运行结果没变                            | 资源同步发生在构建时，且删除源码资源不会清理运行目录旧副本                                         | 重新构建；必要时手动清理运行目录                                                 |
| 物体画不出来                                        | 材质 `RenderMode` 是 `Opaque` 但绑了透明纹理；或材质没绑定（`isBound()` 为假）             | 显式 `setRenderMode(RenderMode::AlphaBlend)`；确认 `setRenderable` 成功 |
| 透明物体互相遮挡/穿插看起来不对                              | 排序是**按物体参考点**的，不支持相交网格                                                | 用 `setSortOrigin` 调整参考点；或拆分网格                                    |
| 单轴负缩放的模型背面朝外                                  | 绕序被镜像翻转                                                               | 开启 `setCorrectMirroredWinding(true)`                             |
| PBR 材质发白/发灰                                   | 没开 `linearHdr`，或旧 Shader 自己编码了 sRGB 造成二次编码                            | 开 `config.linearHdr`；旧 Shader 声明 `setShaderOutputsSrgb(true)`    |
| 方向光阴影没出现                                      | 需要 `linearHdr` + PBR 材质 + 支持阴影的 Shader                                | 检查 `Application.cpp` 抛出的说明性异常                                    |
| 画面卡顿或物理抖动                                     | 物理固定步长与渲染帧率不一致的"台阶感"                                                  | 渲染用 `interpolatedBodyState(id, interpolationAlpha())`            |
| 静止物体永远不休眠                                     | 恢复系数让重力压出的微小穿透被反复弹开（历史 bug）                                           | 已通过恢复系数速度阈值修复；自定义参数时注意阈值                                         |
| 退出时崩溃                                         | 销毁顺序错误：先销毁了资源/世界，Scene 还在引用                                           | 遵守 3.3 的铁律，`PhysicsWorld`/GPU 资源必须比 Scene 活得久                    |
| 存档加载报错                                        | 场景引用了无法重建的资源（glTF 实例、临时 Mesh、物理体）                                     | 这些不在保存范围内，需在加载后由应用重建                                             |

## 附录 C：约定速查

| 项目     | 约定                                                              |
| ------ | --------------------------------------------------------------- |
| 坐标系    | 右手系，+Y 向上；相机默认朝 -Z 方向观察                                         |
| 相机相对方向 | 屏幕右方 = `cross(viewDirection, up)`；写成反序会左右颠倒                     |
| 绕序     | 屏幕上**逆时针**为正面；`CullMode::Back` 剔除背面                             |
| 旋转     | 内部只保存四元数；欧拉角约定 `Rx * Ry * Rz`，单位为弧度                             |
| 透明     | 必须显式 `RenderMode::AlphaBlend`；按物体参考点排序，深度写入关闭                   |
| 颜色空间   | 颜色贴图按 sRGB 读入，数据贴图按线性读入；HDR 场景统一在线性空间混合后输出                      |
| 物理     | 单位与渲染一致；`id→下标` O(1) 查找；ID 不复用；固定步长默认 1/60（最多补 4 步）；双方掩码都需匹配才碰撞 |
| 物理半径方向 | 接触法线：平面取平面正侧法线，其余形状"从 A 指向 B"；`separationDirection` 负责统一        |
| 日志     | 分级同步、默认输出 stderr；示例日志在 exe 同级 `logs/`                           |
| 状态     | 状态对象由 `ApplicationStateStack` 独占；切换命令排队到安全边界执行                    |
| UI       | 逻辑像素布局，默认内置英文位图；TTF/OTF 通过 `ApplicationConfig::uiFontPath` 配置        |
| Area     | 只查询重叠集合并派发进入/离开事件，不参与碰撞响应                                |
| 音频     | 主线程调用；一次性音效走 `AudioSystem`/事件队列，持续空间声音才用组件                   |
| 粒子     | 当前是CPU生命周期模拟，应用负责把 `particles()` 转换成绘制数据                       |
| 线程     | 全部主线程；没有后台加载、物理线程或渲染线程                                          |
